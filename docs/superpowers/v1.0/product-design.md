# min-agent-demo V1.0 本地 Web Agent 操作闭环产品需求文档

## 版本定位

V1.0 的主题是“从只读观察器走向本地 Web Agent 操作闭环”。

V0.9 已经具备一条完整、可观察的 Agent 执行机制：用户可以从 CLI 发起目标，Agent 可以使用 Fake 或 DeepSeek 决策模型，执行只读工具、权限工具、固定顺序任务计划和任务产物传递，并在 Trace Viewer 中查看真实运行事件。

但当前体验仍然被拆成两个入口：

1. 用户必须在终端中输入目标并选择启动参数。
2. `write_file` 和 `run_command` 的权限申请只能回到终端处理。
3. Trace Viewer 只能观察当前这一次 CLI 运行，不能从同一个页面继续发起下一次任务。
4. 一次 CLI 任务结束后，Viewer Server 默认只短暂保留，不能作为稳定入口持续使用。

V1.0 只补齐本地网页中的操作闭环：用户启动一次本地服务后，可以在浏览器中发起任务、处理权限申请、查看实时过程并回放历史运行。

V1.0 不是生产级 Agent 工作台，也不改变 V0.9 已经验证过的 Agent 机制。它验证的是：

```text
启动一次本地服务
-> 在网页发起任务
-> Agent 按既有机制运行
-> 在网页处理危险工具权限
-> 在既有 Viewer 中查看实时过程
-> 从运行记录回放历史过程
```

## 要解决的问题

V1.0 要解决的不是“如何让 Agent 更聪明”，而是“如何让一个人不必在终端和浏览器之间来回切换，也能完整操作和理解一次 Agent 运行”。

完成后，用户应当能够：

1. 只启动一次服务，不需要为每个目标重新运行 CLI 命令。
2. 打开页面后立即看到任务输入框和模型选择。
3. 为当前服务会话配置 DeepSeek Key，或直接使用 Fake 模式。
4. 发起任务后自动进入过程查看。
5. 在任意页面看到当前运行状态和待审批提醒。
6. 不回到终端即可批准或拒绝危险工具。
7. 任务完成后继续使用同一个服务发起下一次任务。
8. 从历史运行中打开一份只读回放，并使用同一个 V0.9 Viewer 阅读事件。

## 产品原则

### 1. 网页是操作入口，AgentLoop 仍是执行核心

V1.0 新增的是服务生命周期、网页发起和网页权限处理，不在 HTTP Handler 或前端中复制 Agent 决策、工具执行、任务计划或产物生成逻辑。

所有任务仍必须经过：

```text
AgentLoop -> ToolRegistry -> Tool implementation -> TraceRecorder
```

### 2. Workspace 由服务启动者确定

页面只能展示当前服务绑定的 workspace，不能修改、切换或提交另一个 workspace 路径。

网页发起任务不能扩大 `list_dir`、`read_file`、`write_file` 或 `run_command` 的既有访问边界。

### 3. 一次只运行一个任务

V1.0 不做并发、排队或后台任务池。同一服务进程内最多存在一个非终态运行。

这样可以让当前运行、权限申请、SSE 事件流和页面状态之间保持一一对应，避免在第一个网页闭环版本中引入调度问题。

### 4. 权限决定属于当前活动运行

网页可以处理当前活动运行产生的权限申请，但历史回放不能产生权限、不能处理权限，也不能重新触发工具。

### 5. V0.9 Viewer 内部保持不变

V1.0 明确扩大了 V0.9 的页面边界，允许在 Viewer 外增加全局导航、运行元信息和权限入口，也允许增加“发起任务”和“历史运行”页面。

但 V0.9 Viewer 内部的信息层级、模块顺序、阅读路径和任务产物交互不得重做。

### 6. Key 是服务会话机密，不是项目配置

DeepSeek Key 只服务于当前本地服务进程，不写文件、不写运行记录、不进入 Trace、不进入日志，也不存入浏览器持久化存储。

## 目标用户和使用环境

V1.0 只服务于以下使用方式：

- 单个用户。
- 用户在自己的电脑上启动服务。
- 浏览器和服务位于同一台机器。
- 服务只监听 `127.0.0.1`。
- 使用服务启动参数指定的单个 workspace。
- 运行记录保存到服务启动参数指定的 `runs` 目录。

V1.0 不为局域网共享、远程访问或多用户协作设计。

## 最重要的产品效果

用户启动服务并打开页面后，默认看到“发起任务”。

页面中已经展示固定 workspace，用户只需要：

1. 选择 Fake 或 DeepSeek。
2. 如果选择 DeepSeek，在页面中配置本次服务使用的 Key。
3. 输入任务目标。
4. 点击“开始运行”。

创建成功后，页面自动切换到“过程查看”。用户看到的仍然是 V0.9 Viewer 已经定义的运行状态、原始需求、统计、最终结果、任务计划、任务产物、执行轮次和轮次详情。

当 Agent 申请 `write_file` 或 `run_command` 权限时：

- 全局导航出现“待审批”入口。
- 权限抽屉自动打开。
- 用户可以查看动作、目标、原因、预览和风险。
- 用户批准后，Agent 才能继续执行工具。
- 用户拒绝后，不得出现对应工具的 `tool_started`。
- 用户只关闭抽屉时，权限仍保持等待，不等同于拒绝。

## 信息架构

V1.0 使用一个本地 Web 应用承载三个页面和一个全局权限层：

```text
全局应用外壳
├── 发起任务
├── 过程查看
│   ├── Viewer 外运行元信息
│   └── V0.9 Trace Viewer
├── 历史运行
└── 全局权限抽屉
```

页面可以使用服务端路由、客户端路由或无框架状态切换实现，具体技术形式不属于产品约束。但刷新页面后，服务真实状态必须能够恢复，不能只依赖前端内存。

## 全局应用外壳

### 导航

全局导航固定提供：

1. 发起任务。
2. 过程查看。
3. 历史运行。

导航属于 V1.0 外层结构，不得插入 V0.9 Viewer 内部。

### 当前运行提示

“过程查看”入口旁展示当前运行状态点：

| 状态 | 表现 |
| --- | --- |
| 没有活动运行 | 中性状态 |
| 正在运行 | 运行中状态 |
| 等待审批 | 警示状态 |
| 已完成或失败 | 回到非活动状态，页面仍可查看最后一次运行 |

### 待审批入口

存在待处理权限时，全局外壳显示“待审批 1”。

V1.0 的 AgentLoop 顺序执行工具，因此同一时刻最多有一份待处理权限。入口不能依赖权限抽屉保持打开；抽屉关闭后，入口仍然可见并可重新打开。

权限被批准、拒绝或运行终止后，入口消失。

## 发起任务页面

### 页面职责

发起任务页面只负责配置并创建一份新运行，不承担过程解释、任务计划编辑或历史查看。

### Workspace 展示

- 展示服务启动时解析后的 workspace。
- 明确标记为固定或只读。
- 页面中不提供路径输入、目录选择器或切换按钮。
- 创建任务接口不接受前端传入 workspace；即使请求被人工构造，服务也只能使用启动时固定的 workspace。

### 模型选择

每次运行可以独立选择：

| 模式 | 产品行为 |
| --- | --- |
| `fake` | 默认值；离线、确定性；不得读取或校验 DeepSeek Key |
| `deepseek` | 使用当前服务内存中已配置的 Key；工具仍由本地 ToolRegistry 执行 |

页面不提供自定义模型名称、Base URL、最大 Token 数等高级参数。这些配置如果需要，继续由服务启动参数提供。

一次运行创建后，模型类型被冻结，运行过程中不能切换。

### DeepSeek Key 配置

选择 DeepSeek 时才展示 Key 配置区。

配置规则：

1. Key 输入不能为空或只包含空白。
2. 点击“本次服务使用”后，Key 通过同源本地请求提交给服务。
3. 服务响应只能返回 `configured=true|false`，不得回显 Key、前缀、后缀或掩码值。
4. 请求完成后立即清空输入框。
5. “已配置”只代表服务内存中存在非空 Key，不代表 Key 已通过 DeepSeek 鉴权。
6. Key 的有效性在首次真实模型请求时验证；失败必须形成可观察的运行失败。
7. 页面刷新后可以重新查询“是否已配置”，但不能取回 Key。
8. 服务进程退出后，Key 自动失效。
9. 用户可以在没有活动 DeepSeek 运行时清除 Key。
10. DeepSeek 运行处于 `running` 或 `waiting_permission` 时，清除操作不可用，避免页面承诺与运行实际持有的凭据不一致。

Web 服务模式不要求启动时存在 `DEEPSEEK_API_KEY` 环境变量，也不把环境变量作为页面“已配置”的隐式来源。现有单次 CLI 模式可以继续沿用 V0.9 的环境变量行为，两种入口的密钥来源必须明确区分。

### 任务目标

- 必填。
- 去除首尾空白后不能为空。
- 最大长度为 1000 个字符。
- 页面展示当前字符数。
- 目标按普通文本处理，渲染时必须转义，不能作为 HTML 注入页面。

### 开始运行

满足以下条件时按钮可用：

- 目标合法。
- 当前没有活动运行。
- Fake 模式无需 Key。
- DeepSeek 模式已经在服务内存中配置 Key。

点击后：

1. 页面提交目标和模型类型。
2. 服务端重新执行全部校验，不能只信任按钮状态。
3. 服务创建唯一 `run_id` 并启动 AgentLoop。
4. 接口返回创建成功后，页面自动进入“过程查看”。
5. 如果创建失败，页面停留在当前页并展示可理解的错误，不得伪造一个运行中状态。

### 当前运行卡片

当存在活动运行时，发起任务页展示当前目标摘要、模型和运行状态，并提供“进入过程查看”。

“开始运行”按钮保持禁用，不提供排队或覆盖当前运行的能力。

## 过程查看页面

### Viewer 外运行元信息

V1.0 可以在 V0.9 Viewer 之前增加一条外层运行元信息，至少展示：

- 查看模式：`当前运行` 或 `历史回放`。
- Decision Model：`Fake` 或 `DeepSeek`。
- Workspace：服务绑定的 workspace 展示值。

这条信息不进入 V0.9 Viewer 的模块结构。

### V0.9 Viewer 冻结边界

过程查看必须继续保留以下模块顺序：

```text
运行状态
-> 原始需求
-> 本次任务统计
-> 最终结果
-> 任务计划（仅复合任务）
-> 执行轮次 / 轮次详情
```

关键 DOM 结构继续以 V0.9 实现为基准，至少保留：

- `#current-title`
- `#run-status`
- `#original-request`
- `#run-summary`
- `#final-answer`
- `#task-plan-panel`
- `#task-progress-text`
- `#task-progress-value`
- `#task-list`
- `#task-artifact-panel`
- `#task-artifact-title`
- `#task-artifact-status`
- `#task-artifact-body`
- `#selected-task-label`
- `#round-list`
- `#round-detail`

V1.0 禁止在 Viewer 内部增加：

- 发起任务输入框。
- 模型选择或 Key 输入。
- 批准、拒绝按钮。
- 任务计划编辑。
- 重试、重新运行、暂停、继续或中断按钮。
- 历史运行列表。

### 没有运行时

用户在尚未发起任务时进入过程查看，应看到明确的等待状态：

- 标题说明正在等待任务开始。
- 原始需求说明尚未发起任务。
- 统计值为空或为 0。
- 最终结果说明需要先从“发起任务”提交目标。
- 不显示任务计划。
- 执行轮次区域显示等待事件。

不能用原型示例数据冒充真实运行。

### 当前运行

当前运行通过服务真实状态和 TraceEvent 渲染：

- 页面首次进入时先获取当前运行快照。
- 后续事件继续通过 SSE 实时到达。
- SSE 重连后必须基于同一个 `run_id` 补齐或重放事件，不能把两个运行的事件混在一起。
- 页面刷新后必须恢复当前运行，而不是退回静态初始状态。
- 任务完成或失败后，页面保持最终状态，直到用户发起新任务或打开历史回放。

### 历史回放

从历史运行进入过程查看时：

- 外层模式明确显示“历史回放”。
- 使用指定 run record 的完整事件渲染同一个 Viewer。
- 简单任务不显示任务计划。
- 复合任务的任务状态、进度、产物和轮次必须全部来自该历史记录。
- 历史回放不连接当前运行的事件流。
- 历史回放不能显示或处理当前权限申请。
- 全局待审批入口仍只代表当前活动运行；用户可以从历史页面点击该入口处理当前权限，但不能把权限决定写入历史记录。

## 权限审批

### 适用范围

V1.0 只把现有两类危险工具的确认入口从 CLI 扩展到网页：

- `write_file`
- `run_command`

工具本身的安全边界保持不变。

### 权限抽屉内容

每份权限申请必须展示：

- 所属运行和当前任务。
- 工具名称。
- 申请原因。
- Workspace。
- `write_file` 的目标路径、写入模式和内容预览。
- `run_command` 的 `command_id`、本地注册表解析后的实际参数数组或可理解命令展示、工作目录和风险说明。

页面只能展示运行时已经校验后的权限详情。未知或非法 `command_id` 必须在生成权限申请前拒绝。

### 权限状态

```text
pending -> approved
pending -> rejected
```

- 批准只对本次工具调用有效。
- 拒绝只处理本次申请，并沿用现有 AgentLoop 的失败收敛路径。
- 关闭抽屉、按 Escape、切换页面或刷新页面都不改变 `pending` 状态。
- 同一权限申请只能成功解决一次；重复提交必须返回幂等结果或明确的已处理错误，不能执行两次工具。
- 只有当前 `pending` 申请可以被处理。
- 服务重启、运行中断或运行进入终态后，旧权限申请失效。

### 批准路径

```text
permission_requested
-> 网页展示 pending 申请
-> 用户批准
-> permission_resolved(approved=true)
-> tool_started
-> tool_finished
-> observation_added
-> AgentLoop 继续
```

### 拒绝路径

```text
permission_requested
-> 网页展示 pending 申请
-> 用户拒绝
-> permission_resolved(approved=false)
-> observation_added(permission rejected)
-> AgentLoop 按现有规则失败或输出结果
```

拒绝后不能出现该申请对应的 `tool_started`。

## 历史运行页面

### 数据来源

历史列表只读取 `runs` 目录中的正式运行记录。前端示例数据、内存场景和 TraceEvent 缓存不能成为历史数据源。

### 列表规则

- 默认按创建时间倒序。
- 至少展示目标摘要、运行时间、模型和最终状态。
- 复合任务可以展示完成任务数。
- 当前仍在运行的任务属于“当前运行”，不把未保存的前端状态伪装为历史记录。
- 单个损坏或无法解析的记录不能让整个历史页面空白；该记录应被隔离并形成可理解的加载错误。

### 历史详情

选择一条历史记录后展示：

- 完整目标。
- Decision Model。
- 最终状态。
- 创建和结束时间。
- 任务完成数量。
- 最终回答摘要。
- “查看完整过程”入口。

V1.0 历史页面只读，不提供删除、重命名、再次运行、继续运行或导出。

## 服务生命周期

### 启动

V1.0 新增一个不要求目标参数的长驻 Web 服务入口。最终命令名称由实施计划固定，但必须支持至少以下启动配置：

- Workspace。
- Runs directory。
- 监听端口，允许 `0` 表示自动选择空闲端口。
- 是否自动打开浏览器。
- DeepSeek 模型名称、Base URL、超时和最大输出 Token 等服务级参数。

服务启动时必须先验证 workspace。验证失败或端口绑定失败时，返回配置错误并退出，不能打开一个不可用页面。

服务只监听 `127.0.0.1`，启动成功后打印唯一访问 URL。

### 运行

- 关闭浏览器不停止服务。
- 任务完成后服务继续运行。
- 用户可以在上一任务进入终态后发起下一任务。
- 当前运行状态、待审批状态和最后一次运行由服务端维护，不能只存在浏览器中。

### 停止

用户在启动服务的终端中通过 `Ctrl+C` 停止服务。

如果停止时存在活动运行：

- 运行应尽可能保存为 `interrupted`。
- 等待中的权限申请失效。
- SSE 连接关闭。
- DeepSeek Key 从进程内存中消失。

V1.0 不增加网页“停止服务”按钮。

### 现有 CLI 兼容

现有单次 CLI 入口继续可用，并继续使用终端权限确认和 `DEEPSEEK_API_KEY` 环境变量。

V1.0 的 Web 服务入口不能让以下既有行为退化：

- Fake 模式默认不读取 Key。
- DeepSeek 单次 CLI 只从环境变量读取 Key。
- CLI 权限批准和拒绝事件链保持不变。
- `--no-viewer`、`--no-browser` 和现有退出码语义保持不变。
- 现有 377 项基线测试继续通过。

## 产品级状态模型

### 服务状态

| 状态 | 含义 | 页面行为 |
| --- | --- | --- |
| `ready` | 没有活动运行 | 可以发起任务 |
| `busy` | Agent 正在运行 | 禁止发起第二个任务 |
| `approval_required` | Agent 正等待权限决定 | 禁止发起第二个任务，显示待审批入口 |

`completed` 和 `failed` 属于运行终态，不是服务终态。运行结束后服务回到 `ready`。

### 运行状态

```text
running
-> waiting_permission
-> running
-> completed | failed | interrupted
```

允许路径：

- `running -> completed`
- `running -> failed`
- `running -> interrupted`
- `running -> waiting_permission`
- `waiting_permission -> running`，仅批准后。
- `waiting_permission -> failed`，拒绝并导致运行失败时。
- `waiting_permission -> interrupted`，服务停止时。

所有终态不可再次变回运行中。

### 页面状态来源

页面状态优先级为：

```text
服务端运行快照
-> 指定 run_id 的 TraceEvent
-> 前端渲染状态
```

前端不能根据按钮点击直接宣布运行完成、权限批准或工具执行成功。

## 运行记录要求

V1.0 继续复用现有 JSON run record 和 TraceEvent 体系，不建立第二套页面日志。

每份 Web 发起的运行记录除现有字段外，至少能够确定：

- `run_id`
- `user_goal`
- `workspace`
- `decision_model`
- `status`
- `created_at`
- `finished_at`，终态后存在
- `events`

禁止进入运行记录：

- DeepSeek Key。
- Key 掩码、前后缀或摘要。
- HTTP Authorization 内容。
- 浏览器输入控件值。
- 服务内部的权限等待对象。

权限申请和决定继续通过现有结构化事件表达。

## 产品级接口语义

具体 URL 和 Python 模块由实施计划确定，V1.0 至少需要以下同源能力：

| 能力 | 输入 | 输出或约束 |
| --- | --- | --- |
| 获取服务状态 | 无 | 固定 workspace、服务状态、当前 run_id、Key 是否已配置 |
| 配置 Key | 原始 Key | 只返回是否配置成功，不回显任何 Key 信息 |
| 清除 Key | 无 | 没有活动 DeepSeek 运行时清除 |
| 创建运行 | `goal`、`decision_model` | 返回唯一 run_id；不接受 workspace |
| 获取当前运行 | 无 | 当前运行快照或明确为空 |
| 订阅当前事件 | run_id | 只返回该运行的 SSE 事件 |
| 获取待审批权限 | 无或当前 run_id | 只返回当前有效的 pending 申请 |
| 解决权限 | permission_id、approved | 只能处理一次，决定必须进入 Trace |
| 获取历史列表 | 分页或最小列表参数 | 从 runs 目录读取的摘要列表 |
| 获取历史运行 | run_id | 完整只读运行记录 |

创建第二个运行时，如果已有 `running` 或 `waiting_permission` 运行，服务必须返回冲突，不得覆盖当前运行。

## 安全与隐私要求

### Key 安全

- Key 只保存在服务进程内存。
- 不创建或修改 `.env`。
- 不使用 `localStorage`、`sessionStorage`、IndexedDB、Cookie 或 Service Worker 缓存 Key。
- 不把 Key 放入 URL、查询参数、HTML 属性或前端全局持久状态。
- 服务日志和异常信息不得包含请求体中的 Key。
- Key 配置响应不得回显任何可用于识别 Key 的片段。
- Fake 运行不得访问 Key Store。

### 本地服务请求边界

- 只监听 `127.0.0.1`。
- 不开启跨域访问。
- 修改状态的请求必须校验同源 `Origin`；缺失或不匹配时按明确规则拒绝。
- 校验 `Host` 为当前环回地址和实际端口，避免把任意 Host 当作可信本地请求。
- 所有运行目标、事件内容、文件内容和模型输出在插入 DOM 前必须转义。

### 工具安全回归

- `list_dir` 和 `read_file` 继续限制在固定 workspace 内。
- `write_file` 继续只创建 workspace 内新文本文件，不覆盖文件。
- `run_command` 继续只接受本地注册表中的固定 `command_id`。
- 命令不得经过 shell。
- 未知命令必须在权限申请前拒绝。
- 网页批准不能绕过 ToolRegistry、validator 或 workspace 校验。

## 异常与失败收敛

### 服务启动失败

| 场景 | 结果 |
| --- | --- |
| Workspace 不存在 | 配置错误，服务不启动 |
| Workspace 不是目录 | 配置错误，服务不启动 |
| 指定端口范围无法绑定 | 配置错误，服务不启动 |
| Web 静态资源缺失 | 服务启动失败，不提供残缺页面 |

### 发起任务失败

| 场景 | 页面结果 |
| --- | --- |
| 空目标或超长目标 | 留在发起页，显示字段错误 |
| DeepSeek 未配置 Key | 不允许提交 |
| 已有活动运行 | 返回冲突并提供进入当前运行的入口 |
| 服务端创建失败 | 不切换成虚假运行中状态 |

### 运行失败

- DeepSeek Key 无效、超时、HTTP 非 2xx、空 content、非法 JSON 或非法 action，继续收敛为可观察失败。
- ToolResult 失败继续进入 Observation 和 Trace，不让服务线程崩溃。
- 单次运行失败不能导致整个 Web 服务退出。
- 失败后应保存 run record，服务回到 `ready`。

### 页面断线

- SSE 断开时页面显示连接状态，不把运行标记为失败。
- 页面按受控退避重连。
- 重连后从服务端恢复同一 run_id 的完整状态。
- 浏览器关闭或刷新不自动批准、拒绝或中断权限。

### 历史记录异常

- 不存在的 run_id 返回明确的未找到状态。
- 非法 JSON、缺失关键字段或不支持的记录结构不能作为可信运行渲染。
- 单条异常记录不影响其他历史记录读取。

## 核心场景

### 场景 A：Fake 简单任务

```text
启动服务
-> 默认打开“发起任务”
-> 保持 Fake
-> 输入“请读取 notes.md 并总结”
-> 开始运行
-> 自动进入过程查看
-> Viewer 实时展示 read_file 和最终回答
-> 简单目标不展示任务计划
-> 运行完成后服务继续保持可用
```

### 场景 B：DeepSeek 复合任务成功

```text
选择 DeepSeek
-> 输入 Key 并配置到服务内存
-> 输入标准复合目标
-> 开始运行
-> 自动进入过程查看
-> Agent 生成固定任务计划
-> run_command 申请权限
-> 网页批准
-> Agent 获得当前时间
-> write_file 申请权限
-> 网页批准
-> Agent 创建 summary.md
-> 4 个任务及产物全部完成
-> 历史列表出现该运行
```

### 场景 C：权限抽屉关闭后重新处理

```text
权限申请出现
-> 抽屉自动打开
-> 用户关闭抽屉
-> 运行继续保持 waiting_permission
-> 全局“待审批 1”仍可见
-> 用户切换到其他页面
-> 点击“待审批 1”重新打开抽屉
-> 批准或拒绝
```

### 场景 D：权限拒绝

```text
write_file 权限申请
-> 用户拒绝
-> permission_resolved(approved=false)
-> 不出现 tool_started(write_file)
-> 运行按既有规则失败或给出拒绝后的最终结果
-> 历史记录保留失败过程
```

### 场景 E：历史回放与当前运行隔离

```text
当前运行正在执行
-> 用户打开历史运行
-> 选择一条旧记录
-> 查看完整过程
-> Viewer 显示旧记录的目标、模型、状态、任务和事件
-> 旧记录不接收当前 SSE
-> 如果当前运行产生权限申请，全局入口出现
-> 处理权限后仍只改变当前运行
```

## V1.0 不做

- 不做远程访问、局域网共享、账号、登录或多用户权限。
- 不做多个 workspace，也不允许页面选择或修改 workspace。
- 不做并发运行、任务队列、优先级或后台调度。
- 不做暂停、继续、取消、重试、恢复或重新运行。
- 不做动态修改、增加、删除或重排任务计划。
- 不做网页编辑任务产物或最终回答。
- 不做历史记录删除、重命名、导出或批量管理。
- 不持久化 DeepSeek Key，不创建 `.env`，不提供 Key 管理系统。
- 不允许自定义工具、模型生成的任意命令、shell、管道或重定向。
- 不改变 `write_file` 只创建新文本文件的限制。
- 不做多 Agent、长期记忆、MCP、Hook 或插件系统。
- 不引入前端框架作为产品目标；是否继续使用原生 HTML/CSS/JS 由实施计划按最小路径决定。
- 不做生产部署、TLS、外部反向代理、移动应用或云端同步。

## 产品验收标准

V1.0 只有同时满足以下条件才算完成：

1. 用户启动一次服务后，可以连续完成多次顺序运行，不需要重启服务。
2. 默认页面是发起任务，固定 workspace 清晰可见且不能从页面修改。
3. Fake 和 DeepSeek 可以按运行选择，运行创建后模型被冻结。
4. Fake 模式不读取或校验 Key。
5. DeepSeek Key 只能进入服务进程内存，刷新页面不能取回，服务重启后失效。
6. Key 不进入文件、TraceEvent、run record、日志或浏览器持久化存储。
7. 当前存在活动运行时，第二次创建请求被明确拒绝。
8. 创建运行成功后自动进入过程查看，并显示真实运行而非预设动画。
9. 页面刷新或 SSE 重连后能够恢复同一当前运行。
10. `write_file` 和 `run_command` 可以在网页批准或拒绝。
11. 关闭权限抽屉不等于拒绝，待审批入口可以重新打开同一申请。
12. 每份权限只能处理一次；拒绝后不能出现对应 `tool_started`。
13. 历史运行来自正式 run record，并能用同一个 Viewer 完整回放。
14. 历史回放与当前运行事件和权限严格隔离。
15. V0.9 Viewer 内部模块顺序、关键 DOM、任务产物和轮次交互不退化。
16. 简单任务继续不展示任务计划；复合任务的状态、进度和产物保持一致。
17. 现有 CLI 使用方式、权限链路和退出码不退化。
18. 服务只监听 `127.0.0.1`，页面状态修改请求不接受跨域调用。
19. 窄屏页面没有水平溢出，任务发起、权限和 Viewer 主要内容可读。
20. 所有机制测试、Agent 场景测试和真实浏览器验收通过。

## 测试验收矩阵

### 机制单元测试

新增或修改 `unittest`，至少覆盖：

- 服务启动时固定 workspace，并拒绝不存在或非目录 workspace。
- Web 创建运行只接受目标和模型，不接受前端 workspace。
- 空目标、超长目标、未知模型被拒绝。
- 同一时刻只能有一个活动运行，终态后可以创建下一运行。
- Fake 模型构建路径不访问 Key Store。
- DeepSeek 未配置 Key 时不能创建运行。
- Key Store 只返回是否配置，不提供 Key 读取接口或序列化。
- 活动 DeepSeek 运行期间不能清除 Key。
- Permission Broker 只允许当前申请被解决一次。
- 批准后才允许工具执行；拒绝后没有对应 `tool_started`。
- 关闭或断开网页不改变 pending 权限状态。
- 当前运行快照、SSE 和历史记录按 run_id 隔离。
- 损坏历史记录被隔离，不影响其他记录。
- 服务端只绑定环回地址，并拒绝不可信 Origin 或 Host。
- 现有 CLI 参数、环境变量 Key 和终端权限测试继续通过。

### Agent 场景测试

使用完整 Web 服务和真实 AgentLoop 验证：

| 场景 | 用户目标 | 必须出现 | 禁止出现 |
| --- | --- | --- | --- |
| Fake 简单任务 | `请读取 notes.md 并总结` | `read_file -> observation_added -> final_answer` | 任务计划、Key 访问 |
| 复合任务批准 | 标准四任务目标 | 两次权限事件、任务产物、最终完成 | 未批准先执行工具 |
| 命令权限拒绝 | 标准四任务目标 | `permission_resolved(false)`、当前任务 failed、后续 skipped | `tool_started(run_command)` |
| 写文件权限拒绝 | 读取并生成摘要文件 | 拒绝 Observation、失败结果 | `tool_started(write_file)` |
| DeepSeek 失败 | 使用无效或模拟失败的模型响应 | 可观察的模型失败、failed run record | 服务进程崩溃、Key 泄漏 |
| 并发创建 | 活动运行期间再次提交 | 冲突响应、原运行继续 | 第二个 AgentLoop |
| 顺序运行 | 第一运行终态后再次提交 | 两个独立 run_id 和记录 | 事件交叉 |

真实 DeepSeek 网络调用不是默认自动测试前提。自动测试应使用可控替身验证 Web 服务到 `DeepSeekLLM` 的装配边界；真实 Key 只用于人工验收，且不得进入测试输出。

### 前端源码结构测试

源码级测试至少约束：

- 存在发起任务、过程查看和历史运行三个页面入口。
- Workspace 展示只读，不存在可提交的 workspace 输入控件。
- 模型只提供 Fake 和 DeepSeek。
- Key 输入没有浏览器持久化逻辑，配置完成后被清空。
- 全局存在独立待审批入口和权限抽屉。
- Viewer 外存在运行模式、模型和 workspace 元信息。
- V0.9 Viewer 的关键 ID 继续存在。
- Viewer 内部模块顺序保持不变。
- 发起、Key、权限和历史控件不进入 Viewer 内部容器。
- 简单任务可以隐藏整个 `#task-plan-panel`。
- 所有动态文本使用安全文本渲染或显式转义。

源码测试只能防止结构退化，不能替代真实浏览器验收。

### 浏览器验收

必须启动真实 V1.0 服务并在真实浏览器或等价运行环境中验证：

1. 服务启动后默认发起页真实渲染，不是空白。
2. Fake 任务可以从输入到完成跑通，并自动进入过程查看。
3. DeepSeek 选择、Key 配置、输入清空和清除状态正确。
4. 当前运行时不能发起第二个任务。
5. 权限抽屉自动打开，内容与真实申请一致。
6. 关闭抽屉后待审批入口保留，重新打开后焦点进入可操作控件。
7. 批准后 Agent 继续；拒绝后工具不启动。
8. 页面刷新后当前运行和 pending 权限状态能够恢复。
9. SSE 断开重连不重复事件、不混入其他 run_id。
10. 完成和失败场景的标题、统计、任务进度、任务状态和产物一致。
11. 历史简单任务不显示任务计划。
12. 历史复合任务显示正确任务产物和轮次。
13. 历史回放不能处理历史权限。
14. V0.9 Viewer 模块顺序和主要交互没有变化。
15. 390px 窄屏无水平溢出，导航、表单、抽屉和 Viewer 可读。
16. 浏览器 Console 没有 JavaScript error，也没有包含 Key 的日志。

`browser manual smoke: PASS` 必须来自上述真实页面验证。只检查 HTML、CSS、JavaScript 或测试源码时只能记录为 `NOT RUN`。

### 安全验收

- 扫描源码、运行记录、日志和浏览器存储，确认不存在测试 Key。
- 人工构造带 workspace 的创建请求，确认服务忽略或拒绝该字段。
- 人工构造跨域修改请求，确认服务拒绝。
- 人工重复提交同一 permission_id，确认工具最多执行一次。
- 人工请求历史 run_id 的事件流，确认不会收到当前运行事件。
- 验证 `..`、workspace 外绝对路径和 workspace 外 symlink 继续被拒绝。
- 验证未知 `command_id` 在权限申请前失败。

### 工作区清理

实施和验收可能产生：

- `runs/*.json`。
- 示例 workspace 中的 `summary.md`。
- 临时服务日志。
- 浏览器截图或自动化产物。

自动测试优先使用临时 workspace 和临时 runs 目录，避免污染仓库示例数据。

需要保留的原型、PRD、实施计划和正式验收记录应进入 `docs/superpowers/v1.0/`。临时产物不得进入提交。任何已有文件或目录的删除仍需用户明确确认。
