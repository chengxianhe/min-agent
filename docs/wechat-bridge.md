# 个人微信任务桥接（本机预览版）

## 当前会话模式（用户确认后的目标）

现在推荐使用 `relay`：**本人微信 ↔ 小看板 ↔ 已打开的同一个 Codex 会话**。
微信文字会成为当前会话的用户输入，忙碌时追加指令，空闲时继续下一轮；不会新建独立执行器。
收到的公开回复、工作说明和任务状态来自绑定会话的小看板，权限规则沿用当前会话。
下方旧版只读独立任务说明仅保留作回退与历史记录。

先停止旧监听，确认小看板已绑定目标会话，并在 Codex 打开该会话，再运行：

```sh
sh desktop/build.sh
PYTHONPATH=src python3 -m min_agent_wechat.relay \
  --state-dir "$PWD/runs/wechat" \
  --thread-id <明确绑定的当前会话UUID>
```

使用已扫码的状态目录，不必再次扫码。首次绑定时，二维码和配对码输入显示在原小看板的“连接设置”中。
连接状态、扫码、配对码和停止同步均内嵌在小看板，不需要额外微信窗口；`--window` 仅保留作可选调试入口。
小看板需要运行新版程序，`wechat-source.json` 只登记状态目录，不包含令牌。
只有本机运行中的 Codex 服务、绑定会话和小看板都就绪时才能开始。
服务未运行、会话未加载或不接受直接输入时不会自动启动 Codex、恢复历史或创建新聊天。
运行期间若小看板切换到另一个会话，转发停止，防止消息串台。
当前开发版本已核对 Codex 0.167.0 的本地控制通道和生成协议；这是实验性接口，升级后需重新验证。

执行范围由原会话决定，不再强制只读示例目录。模块不覆盖模型、工作区、沙箱或批准策略，
不回答服务端权限申请；需要审批时仍在原客户端处理，微信中的“同意”不等于系统审批按钮。
普通文字转给当前会话；`进度`、`结果`、`帮助`由本地看板记录回答，不额外调用模型。
长连接、微信轮询、看板同步和本地查询不调用模型。普通微信消息会作为当前会话输入产生模型用量，
与在原会话发消息相同类型的计费行为；上下文长度、任务内容和追加消息频率影响实际用量，不承诺固定费用。
关闭微信转发只停止转发，不停止 Codex 正在执行的任务。

`relay.sqlite3` 独立保存去重记录、投递状态和待发回复，不重放旧版任务。
启用前的消息和公开说明不自动补发；首次启用会推送当前任务概况。
只从同一账号的旧记录复用更新游标和最近回复上下文，不迁移旧任务队列。
明确收到服务端回执后才显示“已送入当前会话”，这只表示输入已接收，不表示任务完成。
发送后断线、回执丢失或进程中断时标为“投递结果不确定”，**不自动重发指令**，避免重复执行。
尚未开始发送时服务暂不可用，消息留在队列。普通公开工作说明最多每 20 秒回传一次，最终回复立即排队。
公开回复沿用小看板长度和脱敏限制，可能截断；不发送内部思考、完整工具输出、历史聊天或凭据。
微信回复失败重试上限仍为 5 次；接口接受不等于用户已阅读。

实现：`local_socket.py`（有界 Unix WebSocket）、`current_session.py`（固定会话消息投递）、
`relay_store.py`（去重和投递收据）、`relay_mirror.py`（看板摘要）、`relay_service.py` / `relay.py`（运行入口）。
`card_binding.py` 与 `desktop/WeChatConnection.swift` 将连接界面合并到原卡片；
`TaskIdentity.swift` 兼容旧版 `wechat-<12位十六进制>` 任务编号，避免旧记录导致整个历史无法读取。
所有这些模块都独立于旧版 `executor.py`，不再调用 `codex exec`。

## 旧版独立任务模式

本人在微信里发文字任务 → 本机独立 Codex 会话 → 小看板显示过程 → 微信收到进度和结果。
这是新增的真实执行入口，不是 Fake 演示，也不会续接当前 Codex 聊天。

## 首次体验

需要已登录的本机 Codex CLI、Python 3.10+、macOS 13+（扫码窗口）。不安装 OpenClaw、微信外挂或全局依赖。
本人微信必须能使用 ClawBot 扫码连接；实际可用性以微信返回为准。

```sh
sh desktop/build-wechat.sh
PYTHONPATH=src python3 -m min_agent_wechat \
  --workspace "$PWD/examples/workspace" \
  --state-dir "$PWD/runs/wechat" \
  --card-dir "$HOME/Library/Application Support/AgentProgressCard" \
  --window "$PWD/build/WeChatLogin"
```

桌面出现二维码后，用自己的微信扫一扫，并在手机上确认。如果微信显示数字配对码，在桌面连接窗口输入。
窗口显示“已连接”后，在微信中的机器人会话发送：

> 读取 notes.md，用一句话说明这个目录有什么用。

支持文字任务、`进度` / `/status`、`结果` / `/result`、`帮助` / `/help`。
状态和结果查询针对最近任务。语音、图片、群聊、文件附件暂不支持。
连接窗口的“停止连接”会停止接收任务和执行器；关闭窗口仅隐藏窗口，不停止服务。
命令行 Ctrl-C 也可停止。电脑休眠、断网、服务退出后不能实时处理；本版没有开机自启。

## 执行边界与成本

- 只接受扫码者的精确 `ilink_user_id`。身份缺失时拒绝启动；不读取其他聊天或聊天数据库。
- 首次体验固定在仓库的公开示例目录，不能通过微信命令切换工作区。
- 每条任务新建 Codex 会话，使用本机登录和实际模型额度。微信轮询、进度展示和查询不调用模型。
- CLI 使用 `--sandbox read-only`、`approval_policy=never`，不继承用户配置或 execpolicy 放行规则。
- 只读沙箱限制写入，**不是只允许读取工作区的文件隔离容器**。工作目录与提示中的读取范围是额外约束；不能把此预览版当作任意不可信用户的执行服务。
- 本版不提供写文件、提交、部署、发送第三方消息或批准项目治理流程的能力。
- 仅展示公开回复、工具名称/状态/脱敏命令，不保存或展示模型内部思考。结果脱敏使用现有卡片规则，不能保证识别所有形式的敏感信息。

## 存储与恢复

状态目录权限 0700；凭据、SQLite 数据库、状态文件使用 0600。`runs/wechat/`、`build/` 均忽略入库。
`credentials.json` 含登录令牌，`bridge.sqlite3` 含用户任务和回复上下文；不要上传、截图或分享这些文件。
同一目录只允许一个服务进程，工作目录和绑定账号不能悄悄更换。

收件去重、任务入队、回执和更新游标在一个 SQLite 事务中提交。队列上限 10 条，同一时间只执行一条，单次执行上限 10 分钟。
崩溃重启后正在执行的任务标为中断，不自动重跑；已排队任务会继续。卡片也会更正中断状态。
回复先落盘，再发送；失败最多自动尝试 5 次，每次间隔至少 30 秒，并保持同一 `client_id`。
网络中断时无法保证微信侧绝不重复显示回复；不承诺网络层恰好一次投递。
结果每段最多 2800 字，保留上限约 12000 字。中间公开说明最多每 30 秒回传一次。
连接窗口显示待发送回复数量；达到重试上限的回复仍保留，可在网络恢复后发送“结果”重新获取最近结果。
登录失效时服务停止，需使用新的状态目录重新扫码；旧目录保留作记录，不跨账号重放任务。

## 代码与协议来源

- `src/min_agent_wechat/ilink.py`：HTTPS iLink 文本收发，禁止自动 HTTP 跳转，返回地址仅接受微信 HTTPS 域名。
- `login.py`、`files.py`：本人扫码/配对码、凭据和本机状态。
- `database.py`：持久化去重、单任务队列和待发送回复。
- `executor.py`、`service.py`：只读 Codex 子进程、退出码/完成事件校验、超时与服务停止。
- `card.py`、桌面 `watcher.remote_snapshot`：按任务标识隔离微信记录与当前桌面聊天。
- `desktop/WeChatLogin.swift`：独立扫码/连接状态窗口；原小卡片仍只读。

协议核对来源为腾讯发布的 npm 包 [`@tencent-weixin/openclaw-weixin` 2.4.10](https://www.npmjs.com/package/@tencent-weixin/openclaw-weixin)。
只阅读公开协议结构，未运行其安装脚本；本模块是独立客户端，不是腾讯官方插件，也不代表腾讯承诺第三方实现兼容。
使用 `bot` app ID / bot_type 3，协议版本 2.4.10，`bot_agent=MinAgent/0.1` 如实标识实现。
公开说明见 [腾讯 ClawBot 接入文档](https://cloud.tencent.com/document/product/1831/137450)、
[OpenClaw 微信渠道文档](https://docs.openclaw.ai/channels/wechat)、
[Codex exec 官方文档](https://learn.chatgpt.com/docs/developer-commands#codex-exec)。
