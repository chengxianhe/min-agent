# 微信桥接接续（公开脱敏版）

本文件仅保存功能范围、验证方式和未完成项。个人称呼、联系人名称、真实会话/任务编号、
本机绝对路径、私聊原文和扫码凭据不随源码提交。本机详细接续放在 Git 忽略的 `build/local-handoff/`。

## 已实现

- macOS 原生卡片展示概览、过程、工具、结果；支持任务历史、分类和失败筛选。
  本地记录有数量和大小限制，不展示内部思考，不自动批准操作。
- 本人微信通过 `relay` 连接显式绑定的已有 Codex 会话；活动轮次追加消息，空闲时开始下一轮。
  不新建、分叉或恢复其他会话，不覆盖模型、工作区、沙箱或审批策略。
- 扫码、配对码、连接状态和停止同步内嵌在卡片；独立连接窗口仅供调试。
- 收件去重、投递收据、待发送回复持久化；投递结果不确定时不自动重发任务。
- 兼容旧版严格格式的 `wechat-<12位十六进制>` 任务编号，避免单条旧记录使整个历史读取失败。
- 旧版独立只读执行入口保留供回退，与当前会话转发模式明确区分。

用法、执行边界、协议来源和存储说明见 [微信桥接说明](wechat-bridge.md)，
看板分类说明见 [桌面卡片说明](desktop-card.md)。

## 已有验证及限制

- Python 全量 505 项测试通过；本机真实微信输入进入绑定会话，并收到进度/回复。
- Swift 卡片构建与签名通过；原生连接状态、大小限制、历史解码、分类筛选与旧编号兼容检查通过。
- 实际旧历史记录曾复现解码失败；修复后可读取。私有记录不作为公开测试夹具，测试使用虚构数据。
- 连接面板离屏渲染检查通过；不以此代替真实桌面点击验收。
- 未单独记录真实空闲唤醒、长期运行、重启后恢复的完整联调；没有开机自启或进程托管。
- 系统桌面控制曾能读取微信画面，但点击/滚动失败，后续截图空白；
  本机显示正常也不能证明控制接口可用。未验证普通联系人私聊的自动读取或发送。
- 本项目只接收扫码本人发给机器人的消息，不接管联系人列表、普通私聊或群聊。
- 轮询、看板同步及本地进度查询不调用模型；普通任务输入会使用绑定会话的模型额度。

## 暂停中的候选方向：广告投稿到 X

需求是由指定投稿人提交广告，程序将正文发布到账号所有者授权的 X 账号。
此方向目前只作讨论记录；尚未开发投稿入口、配置 X 发布授权或发送任何真实帖子。

候选流程：

1. 为投稿人建立独立的微信连接，与账号所有者的 Codex 控制会话隔离。
2. 投稿人自行扫码后，在机器人对话中发送 `@ai小助手 广告正文`；这是文字前缀，
   发在普通联系人私聊中不会被当前桥接接收。
3. 程序校验发送者、前缀和长度，执行去重；正文只作为发布数据，不解释成任务或工具指令。
4. 通过获得账号所有者授权的 X 发布接口发送正文，回传帖子链接或失败原因；
   发送结果不明时避免自动重复发布。原文转发无需逐条调用模型。

下次先确认：纯文字还是含图片、目标账号的 API 权限及费用、独立扫码连接是否实际可用，
以及是否影响投稿人的已有绑定。方案和改动文件确认后再实现，不默认安装新的平台或替换看板。

原始日志和截图仅留在本机，不入库。脱敏扫描不是对任意敏感内容的识别保证。

## 完成回复缺失修复

基线为 `b62c0d2`。真实记录使用 `AgentMessage.phase=final_answer`，原采集器仅识别
`final`，导致完成回复漏收。另一个原因是后续工作未创建新的显式任务，旧任务的结束时间
阻止后来回复进入任务归档。用户已批准修复采集兼容、最新回复展示及本机更新，暂不提交或推送。

- 将两种公开完成标记统一为 `final`；保留单条脱敏 `latest_reply`，不被 30 条工作记录窗口挤掉。
- 当前任务页单独显示“当前会话 · 最近回复”，不受旧任务结束时间约束；历史任务页不混入当前会话回复。
  回复不自动改变任务状态或代表人工验收。助手开始新任务时仍须显式调用 `begin`。
- 采集器重启补读的记录标为回放；微信不主动重发回放消息，但“结果”查询可读取恢复后的最新回复。
- 用虚构数据验证实际标记、去重、脱敏、跨会话隔离、已结束任务边界、回放及原生解码。
  本机验证证据保存于忽略目录 `build/final-reply-fix/`，不上传聊天原文或真实会话标识。

知识沉淀评估：本项目记录协议兼容事实与测试，未新增跨项目治理知识。
